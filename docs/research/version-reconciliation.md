## Features that are not0.4-only

The six shell hash matches also prevent an easy mistaken conclusion: **ChatGPT/Copilot/Grok subscriptions, automatic updates, renderer sandbox/context isolation, desktop request-capability header, loopback server, and main-process lifecycle were already part of0.3.8's selected shipped shell.** The presence of implementation bytes does not prove successful account auth/update execution.

Selected source files are byte-identical between tag and main for graph canvas/view, reasoning-chain table, plan diagram, demo/SVG cards, session Find, keyboard dispatch, extraction coverage, extraction pipeline, graph deletion and birth-session clusters. See JSON for their source hashes. Their semantics in the product/engine catalogs are therefore not additions introduced by0.4.0, even though this follow-up did not hash their compiled installed counterparts.

Source0.3.8 already supports teaching/practice modes, graph-context selection, Markdown export, question confidence/thinking, live steering, original dictation with warm-token/reconnect behavior, per-session model selection and compaction. Newer-only distinctions above are extensions or corrections; avoid describing all of those broad capabilities as new.

## Reconstruction baseline and remaining checks

CoquiLearn should target **0.4.0 source parity** as the full reference feature set while validating installed0.3.8 interactions separately. Use U/E IDs for capability requirements and V IDs for version-sensitive behavior. macOS is the first target; a future iOS companion has different local-file/CLI/runtime constraints.

This follow-up did not run upstream tests or inspect user data. Still unknown: entire compiled-server/UI identity, effective dependency lock resolution in installed app, live provider behavior, real permissions, actual repaired failure paths, performance and successful updater installs. Do not upgrade a source-derived statement into observed runtime behavior without the matching evidence.
